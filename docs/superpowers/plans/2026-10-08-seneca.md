# Seneca Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seneca, the owner's counsel for work at Synecta, is live in OpenClaw and
delivers the morning standup — produced on the laptop by `/daily-standup` — to
Telegram as a letter on weekdays at 09:30 Asia/Novosibirsk.

**Architecture:** A systemd user timer on the laptop runs `laptop/seneca-standup`
(`collect.sh`, then `claude -p` with the skill's rules) and pipes the summary over
SSH into `bin/standup-intake` on the server. The intake stores it in Seneca's
workspace and runs one `openclaw agent --deliver` turn in `agent:seneca:main`.
Questions and work reminders reach Seneca through Zeus, like every other god.

**Tech Stack:** bash, systemd user units, Claude Code CLI 2.1.x, OpenClaw 2026.9.7
CLI, GitHub Actions deploy over SSH.

**Spec:** `docs/superpowers/specs/2026-10-08-seneca-design.md`

## Global Constraints

- OpenClaw 2026.9.7 on `openclaw@kz-openclaw`; CLI from
  `/home/openclaw/.openclaw/tools/node/bin` (pinned by `remind-impl/remind-lib`);
  server clock UTC.
- Agent id `seneca`; workspace `/home/openclaw/.openclaw/workspace-seneca`;
  standups in `standups/<YYYY-MM-DD>.md`.
- Seneca's tool policy = Heracles's (README "Tool policies"); exec allowlist =
  `/home/openclaw/bin/agents/seneca/remind*`.
- Intake exit codes: `0` delivered, `2` usage/bad date/empty or oversized (> 65536
  bytes) input, `4` no workspace, `5` no owner chat, `6` `openclaw agent` failed
  (file kept). Nothing is stored or sent before validation passes.
- Laptop timer `OnCalendar=Mon..Fri *-*-* 09:30:00`, `Persistent=true`; window `3d`
  on Mondays, else `1d`; failure notification title
  `Сенека: стендап не отправлен — <step>`.
- The letter: greeting line, summary verbatim between `<<<SUMMARY`/`SUMMARY>>>`
  (markers omitted), one thought for the day, `Vale.`; plain reply, no `message`
  tool, no `NO_REPLY`; nothing written to `MEMORY.md` per standup.
- Persona placeholders: `{{NAME}}`, `{{USERNAME}}`, `{{CHAT_ID}}`, `{{REMIND_BIN}}`.
- Git: stage explicit paths only; never stage or revert the owner's uncommitted
  `.gitignore` change; semantic English messages in the repo's style; one commit
  per verified increment, tests with their implementation.

## Decisions made where the spec left room

- The intake resolves the owner chat before storing, so exit 5 stores nothing.
- Whitespace-only stdin counts as empty.
- The laptop job retries `ssh` only on its own connection failure (rc 255), three
  tries 20 s apart, so a laptop waking from sleep survives a late network; intake
  rejections are never retried. `SENECA_SSH*` overrides exist for tests.
- The prompt names the heading for the window (`1d` «За последние 24 часа», `3d`
  «За 3 дня»), as the skill's heading rule asks.
- Persona files ship as in `gods/`; OpenClaw's doctor may later fold `TOOLS.md` into
  `AGENTS.md`, as for the other gods.
