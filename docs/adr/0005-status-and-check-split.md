# `pantheon-status` and `pantheon-check` are two binaries over one module

Both are thin front ends to the same monitor module, split by consequence: `pantheon-status` is read-only and safe to run before initialization, while `pantheon-check` may send owner-only failure alerts and therefore runs only under approved activation (`README.md:363-367`). The rejected alternative was one command with an `--alert` flag: a single binary whose default invocation page someone is a footgun, and one that cannot be recommended as a first diagnostic step. The consequence is that alerting needs an explicit `--initialize` baseline and a separately enabled timer, so an un-initialized install cannot page anyone, and re-initialization is refused rather than silently resetting dedupe (`README.md:484-493`).
