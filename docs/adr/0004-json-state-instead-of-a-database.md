# Durable lifecycle state as JSON files with receipts, not a database

The standup pipeline keeps one locked JSON record per date — attempt id, input hash, stage timestamps and native evidence — and the monitor keeps a single `monitor/state.json` ledger of seen alerts and dispatched intents; both are written atomically at mode 0600 under a 0700 directory (`README.md:229-240`, `bin/pantheon_ops/state.py:117-186`, `bin/pantheon_ops/monitor.py:99,187`). The rejected alternative was SQLite or Postgres: a schema to migrate and, for Postgres, a second service to keep available, to store a few hundred small records a year that an operator must be able to read and copy by hand during an incident. Two consequences are worth recording: `submission_unknown` exists as an honest terminal-ish state meaning "we submitted and cannot prove the outcome", and nothing retries implicitly — an uncertain attempt waits for a human decision.
